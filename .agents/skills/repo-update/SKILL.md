실제 작업을 보존하면서 불필요한 로컬 산출물을 정리하고 원격 변경을 통합한다. 이 스킬 호출은 아래 기준으로 확인된 불필요한 변경의 제거를 허용한다. 커밋과 push는 포함하지 않는다.

## 로컬 정리

1. 현재 브랜치, upstream, staged·unstaged·untracked 변경과 진행 중인 merge/rebase를 확인한다. 병합 중이면 먼저 상태를 파악하고 충돌 파일을 정리 대상으로 취급하지 않는다.
2. 변경 내용, 생성 목적, 코드·에셋 참조와 빌드 사용 여부를 확인해 정리 대상을 고른다. 일회성 AI 검증 코드, 확인을 마친 프리뷰·스크린샷·로그, 재생성 가능하며 프로젝트에 필요 없는 자동생성 변경이 대상이다. 파일명, 폴더명, 확장자 또는 AI가 만들었다는 이유만으로 제거하지 않는다.
3. 기능 코드·에셋·데이터, 유지하는 테스트·검증 도구, 빌드에 필요한 생성 파일, Unity 참조 에셋과 meta는 보존한다. 사용자가 요청한 결과물, 유일한 복구본, 실행 중인 작업의 출력도 보존한다. 용도가 불명확하면 남겨두고 확실한 대상만 정리한다.
4. 실행 직전에 제거할 경로와 이유를 짧게 알린다. 대상이 확실하면 추가 확인 없이 진행한다.
   - tracked 파일은 불필요한 로컬 변경만 HEAD 기준으로 되돌린다. staged 변경도 검토하고 해당 부분만 제거한다. 실제 작업이 섞인 파일은 파일 전체를 복원하지 않는다.
   - untracked 산출물은 확인된 파일만 삭제한다. ignored 파일은 알려진 일회성 출력 경로만 검토하며 캐시·환경설정·로컬 데이터 전체를 청소하지 않는다.
   - Unity 에셋을 삭제하면 해당 meta도 함께 처리하되 유지할 파일의 meta는 보존한다. 이미 커밋된 파일 자체를 없애는 리팩터링은 이 정리의 범위가 아니다.
   - 재귀 삭제는 실제 절대 경로와 하위 내용을 확인하고 저장소 안의 검토한 출력 디렉터리에만 적용한다. Windows에서는 `Remove-Item -LiteralPath` 등 한 셸의 네이티브 명령을 사용한다.

## 원격 통합

정리 후 [pull-merge](../pull-merge/SKILL.md)를 읽고 실행한다. 남은 로컬 변경과 스테이징 상태를 보관하고 pull 및 충돌 해결 후 복원한다. 정리 전 stash가 있다면 불필요한 산출물이 복원되지 않도록 복원 결과도 확인한다. 기존 사용자 stash는 삭제하지 않는다.

- fast-forward 또는 이미 최신 상태면 로컬 작업 복원까지 완료한다.
- 이력이 갈라지면 충돌을 해결한 뒤 merge commit 대기 상태로 남긴다. 로컬 작업은 pull-merge 규칙대로 stash에 보존한다. 커밋 없이 병합까지 완료했다고 보고하지 않는다.
- 전체 `reset --hard`, `git clean`, 경로를 한정하지 않은 checkout/restore, `ours`·`theirs` 일괄 적용, rebase, push는 하지 않는다.
- 필요한 검증 후 원격 통합 결과, 제거한 항목, 보존한 불명확한 항목, 남은 충돌·커밋 대기·stash를 간단히 보고한다.
