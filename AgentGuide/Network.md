# 네트워크 필수 규칙

- 메인 인증 → 게임서버의 일회용 배정권 교환 → 아웃게임 → 데디케이티드의 일회용 입장권 교환 순서를 유지한다. 계정·프로필·구매·참가 권한은 서버가 검증한다.
- 로비 채팅은 게임서버 세션으로 인증하는 별도 WebSocket을 사용한다. 데디케이티드의 방 채팅과 기록·참여자를 섞지 않는다.
- 게스트 ID와 무작위 비밀값은 첫 인증 전에 기기 보안 저장소에 보관하고 서버에는 비밀값의 해시만 저장한다. Google 연동은 인증된 게스트의 계정·재화를 유지하며, 연동 후 접속은 Google 인증을 요구한다. 연동용 Google 챌린지도 메인 세션에 귀속시킨다.
- `ServerContracts.cs`와 `GameplayEnvelope.cs`는 Unity와 .NET 서버가 공유한다. 필드 또는 게임 규칙 변경은 클라이언트·서버를 함께 배포한다.
- 내부 방 UUID와 사용자 입력 `RoomCode`를 구분한다. 빈 방은 공개 목록에서 숨기며, 삭제는 미사용 입장권·교환 중 입장·장애 재접속 유예를 확인한 게임서버의 승인으로 처리한다.
- 데디케이티드가 게임 판정·개인별 비밀 상태·캔버스 기록을 소유한다. 중도 일반 참가자는 이번 경기를 관전하고 다음 대기방의 빈자리에만 배정한다. 명시적 관전 선택은 유지하며 재접속은 기존 ID·역할·점수를 복원한다. 비밀 제시어를 공용 상태에 넣지 않는다.
- 방 옵션은 데디케이티드가 방장 권한과 대기실·경기 종료 상태를 검증한 뒤 변경한다. 클라이언트는 서버가 보낸 설정을 반영한다.
- 배포는 Ubuntu 24.04 x64의 `drawliar-dev` Compose와 `DrawLiar-Server` Jenkins 작업을 사용한다. 같은 머신의 Kona 서비스·DB·배포 경로를 변경하지 않는다. DB 볼륨과 `/srv/drawliar/dev/.env`, 인증서를 배포물에 포함하거나 삭제하지 않는다.
- 개발 인증·HTTP/WS는 명시적으로 허용한 로컬 개발 환경에만 사용한다. 공개 연결은 HTTPS/WSS로 유지하며 비밀 키·토큰·비밀번호를 로그에 남기지 않는다.
- Android CI는 로컬 작업 트리를 별도 작업 폴더에 복사한다. 이를 원격 커밋 빌드로 취급하지 않는다. 서명 키·웹후크는 Jenkins Credentials로 전달하고, Firebase의 임시 APK 다운로드 링크는 Discord 전송 뒤 삭제하며 로그·보관 산출물에 넣지 않는다.
- Unity Mono는 `ClientWebSocket`의 인증서 콜백을 적용하지 않는다. WSS는 `DrawWebSocketClient`의 `SslStream` 검증과 관리형 WebSocket을 사용한다.
